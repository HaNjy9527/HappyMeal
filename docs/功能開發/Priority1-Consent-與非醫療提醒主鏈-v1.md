# Priority 1｜Consent 與非醫療提醒主鏈 v1

- 文件名稱：Priority 1｜Consent 與非醫療提醒主鏈
- 版本：v1
- 日期：2026-04-26
- 狀態：Draft
- 用途：把 PRD v1 尚未補齊的 Consent 與非醫療提醒主鏈拆成可追蹤的補完項目

---

## 1. 文件定位

本文件處理的是 PRD v1 gap-closing plan 中的 Priority 1。

它不是新的 PRD，也不是 Step 2 ticket 清單。

本文件只回答三件事：

1. 這條主鏈目前還缺什麼
2. 要先補哪些使用者可見流程
3. 什麼叫做這個 Priority 已經補齊

---

## 2. 目前問題

目前 repo 已有 Consent API、政策版本保存與 consent 狀態檢查能力，但從使用者角度仍有幾個缺口：

1. 首次登入後，還沒有完整的 Consent Intro 主鏈
2. 非醫療用途提醒尚未覆蓋到所有建議相關畫面
3. 使用者在進入分析與建議流程前，還看不到一條清楚、可理解、可完成的同意流程

---

## 3. 目前狀態

目前可視為已知進度如下：

1. 後端已具備 consent 紀錄、版本保存與狀態查詢能力
2. consent 相關文案已有草稿與獨立文件，可作為前端導入基礎
3. 系統邏輯上已經把 consent 視為正式資料，而不是一次性的靜態頁面

目前仍未完成的重點：

1. 首次登入後，前端尚未導入完整的 Consent Intro 與同意主鏈
2. Analysis Result、History Detail 與建議區塊的非醫療提醒仍未完整覆蓋
3. 未同意前的前端導引、guard 與返回 consent 路徑仍未整理完整

---

## 4. 目標

讓使用者從首次登入到第一次完成分析時：

1. 能清楚看到隱私政策與非醫療用途說明
2. 必須完成兩項同意後才進入建議流程
3. 在 Analysis Result、History Detail 等關鍵畫面都能再次看到適當的非醫療提醒

---

## 5. 工作拆解

### P1-01 首次登入導入

目標：首次登入後先看到 Consent Intro，而不是直接略過。

包含：

1. consent 狀態判斷與轉向
2. Intro 卡片與簡短說明
3. 手機上可閱讀的文案結構

### P1-02 勾選與送出主鏈

目標：讓兩項同意可被清楚閱讀、勾選與送出。

包含：

1. 隱私政策 checkbox
2. 非醫療用途說明 checkbox
3. 兩者都勾選後才可繼續
4. 文案區塊可收合，降低手機壓力

### P1-03 分析流程前置保護

目標：未同意前不得直接進入分析與建議流程。

包含：

1. analysis 入口前的 consent 檢查
2. confirm 或建議流程前的 guard
3. 錯誤訊息與返回 consent 的導引

### P1-04 非醫療提醒覆蓋

目標：在結果與歷史相關頁面補齊提醒。

包含：

1. Analysis Result 顯示提醒
2. History Detail 顯示提醒
3. 相關建議區塊保留 wellness guidance 語氣

---

## 6. 明確不做

1. 法務後台
2. 多版本政策管理介面
3. 額外登入方式管理
4. 超出 MVP 的合規流程擴張

---

## 7. 驗收條件

1. 首次登入後，使用者會先進入 Consent Intro
2. 未勾選兩項同意前，不能進入分析與建議流程
3. Analysis Result 與 History Detail 皆可看到非醫療用途提醒
4. 手機版上，文案區塊可閱讀且不會形成過重資訊牆
