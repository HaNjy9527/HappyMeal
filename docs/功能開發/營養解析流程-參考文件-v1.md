## 1. 概覽（與辨識流程的關係）

**本流程的起點是使用者按下「確認」**，不是圖片上傳。兩條流程完全獨立：

```
圖片上傳流程  →  回傳候選清單（food_name + portion）
                        ↓
              使用者在前端檢視、可修改
                        ↓
              使用者按確認（POST /analyses/{id}/confirm）
                        ↓
              ← 本文件涵蓋的範圍 →
```

辨識流程的詳細說明請參閱：[圖片辨識流程-參考文件-v1.md](./圖片辨識流程-參考文件-v1.md)

**本流程的核心問題：**  
「根據使用者給的 `food_name`、`normalized_food_name`、`portion_value`、`portion_unit`，算出這份食物的 kcal、蛋白質、脂肪、碳水。」

**涉及的服務模組：**

| 模組 | 路徑 | 職責 |
|------|------|------|
| `analysis_confirm.py` | `app/services/` | 入口：逐筆呼叫營養解析、計算加總、存入 DB |
| `nutrition_resolution.py` | `app/services/` | 協調來源選擇與份量換算 |
| `food_mapping.py` | `app/services/` | 將食物名稱映射到 canonical key |
| `nutrition_catalog.py` | `app/services/` | 精選關鍵字目錄查詢 |
| `rag_lookup.py` | `app/services/` | pgvector 向量查詢（衛福部資料） |
| `portion_resolution.py` | `app/services/` | 單位換算與克重估算 |

## 3. 各層詳細說明

### 3.1 確認入口 — `analysis_confirm.py`

**前置條件：**

| 條件 | 失敗時 |
|------|--------|
| `analysis.status == AWAITING_CONFIRMATION` | HTTP 409 Conflict |

**`FoodAnalysisItem` 存入的欄位（從 `NutritionResolutionResult` 取得）：**

| 欄位 | 說明 |
|------|------|
| `food_name` | 使用者最終確認的食物名稱 |
| `normalized_food_name` | snake_case 英文 key |
| `canonical_food_name` | 系統解析後的標準 key（如 `generic_protein`）|
| `nutrition_source` | 營養數值來源（見第 4 節）|
| `is_estimated` | 是否為估算值 |
| `resolved_weight_g` | 最終換算克重 |
| `weight_estimation_method` | 克重換算方法 |
| `kcal` / `protein_g` / `fat_g` / `carb_g` | 實際營養數值 |

---

### 3.2 營養來源選擇 — `nutrition_resolution.py`

`select_nutrition_source()` 依優先順序嘗試各來源，取第一個命中的：

```
resolve_official_source()
    ├─ RAG 命中 → 使用（source: "rag_official"）
    └─ 關鍵字目錄命中 → 使用（source: "official_source"）
    └─ 都沒中 → 進入下一層

resolve_canonical_mapping_source()
    ├─ direct 命中 → 使用（source: "preset"）
    ├─ alias 命中 → 使用（source: "alias_mapping"）
    ├─ keyword 命中 → 使用（source: "keyword_fallback"）
    └─ 都沒中 → fallback

resolve_fallback_source()
    → 固定使用 "generic_mixed_meal"（source: "default_fallback"）

apply_special_source_guards()
    → 若偵測到包裝飲料且目前 canonical = "generic_mixed_meal"
    → 改用 "generic_unsweetened_drink"（source: "drink_fallback"）
```

---

### 3.3 RAG 向量查詢 — `rag_lookup.py`

**觸發條件：** 有 `db` session 可用時執行（無 db 時跳過）。

**流程：**

1. 組合查詢字串：`"{normalized_food_name} {food_name}"`
2. 呼叫 OpenAI Embeddings API（`text-embedding-3-small`）取得向量
3. 對 `food_nutrition_embeddings` 表執行 pgvector cosine 距離搜尋：
   ```sql
   SELECT ... FROM food_nutrition_embeddings
   ORDER BY embedding <=> CAST(:vec AS vector)
   LIMIT 1
   ```
4. 距離 ≤ 閾值（`COSINE_DISTANCE_THRESHOLD = 0.20`，等同相似度 ≥ 0.80）→ 命中
5. 命中時回傳 `FoodNutritionEmbedding`（含 `kcal_per_100g` 等衛福部原始數值）

**RAG 命中後的 Preset 建立：**

```python
NutritionPreset(
    portion_unit="g",
    weight_g=Decimal("100"),   # 衛福部數值均為 per 100g
    kcal=match.kcal_per_100g,
    protein_g=match.protein_g_per_100g,
    fat_g=match.fat_g_per_100g,
    carb_g=match.carb_g_per_100g,
)
```

`resolve_portion()` 會依使用者實際份量計算 multiplier，正確縮放至實際攝取量。

**SQLite 相容性：** `rag_lookup.py` 整體包在 `try/except` 內，在 SQLite（測試環境）中不支援 `<=>` 運算子時，直接回傳 `None`，降級至關鍵字目錄。

**前提：** `food_nutrition_embeddings` 表需先執行以下兩支腳本才有資料：
1. `scripts/import_nutrition_xlsx.py` — 匯入衛福部 Excel
2. `scripts/generate_embeddings.py` — 生成向量

### 3.4 Canonical Key 映射 — `food_mapping.py`

`resolve_canonical_food()` 嘗試以下四個層次，依序命中即停止：

#### a. 直接命中（`CANONICAL_FOOD_KEYS`）

`normalized_food_name` 完全等於某個 canonical key → `match_type: "direct"`

```python
# 範例：normalized_food_name = "boiled_egg"
→ canonical_food_name = "boiled_egg"（直接命中）
```

#### b. 別名映射（`ALIAS_MAPPING`）

`normalized_food_name` 存在於 alias 字典 → `match_type: "alias"`

```python
# 範例：normalized_food_name = "lu_rou_fan"
→ ALIAS_MAPPING["lu_rou_fan"] = "minced_pork_rice"
→ canonical_food_name = "minced_pork_rice"
```

#### c. 關鍵字規則（`KEYWORD_RULES`）

若前兩層都沒中，組合 `"{normalized_food_name} {food_name}"` 轉小寫，去除 `_` 和 `-`，對 `KEYWORD_RULES` 逐條比對：

```python
KEYWORD_RULES = [
    ("generic_condiment", ("sauce", "dressing", "dip", "醬", "醬汁")),
    ("generic_garnish",   ("ginger", "scallion", "garlic", "sesame", "薑", "蔥", "蒜", "芝麻")),
    ("boiled_egg",        ("egg", "omelette", "蛋", "水煮蛋", "荷包蛋")),
    ("generic_rice",      ("rice", "porridge", "grain", "飯", "粥", "穀")),
    ("generic_protein",   ("chicken", "beef", "pork", "tofu", "salmon", "fish", "shrimp", "雞", "牛", "豬", ...)),
    ("generic_mixed_meal",("bento", "meal", "curry", "noodle", "pasta", "便當", "套餐", ...)),
    ...
]
```

**特殊組合邏輯：**  
同時命中 `generic_rice` + `generic_protein` → 強制映射為 `generic_mixed_meal`（米飯加蛋白質 = 套餐）。

#### d. 預設 Fallback

所有規則都沒中 → `canonical_food_name = "generic_mixed_meal"`，`match_type: "default_fallback"`。

### 3.5 份量解析 — `portion_resolution.py`

`resolve_portion()` 將使用者輸入的 `portion_unit` 換算成克重，再計算 `multiplier`：

```
multiplier = resolved_weight_g / preset.weight_g
```

**換算優先順序：**

1. **單位換算表（`UNIT_CONVERSION_TABLE`）：** `ml`、`l`、`oz`、`tbsp`、`tsp`、`g`、`kg` 等直接換算到克
2. **容器預設（`CONTAINER_DEFAULTS`）：** `bottle`、`can`、`carton` 等依飲料類型設定預設克重
3. **Preset 預設單位：** 使用者輸入的單位 = preset 的 `portion_unit` → multiplier 直接等於 portion_value
4. **Serving 預設：** 其他情況 multiplier = 1.0

**`NutritionPreset` 結構：**

```python
@dataclass(frozen=True)
class NutritionPreset:
    portion_unit: str       # 標準單位（bowl、pcs、plate 等）
    weight_g: Decimal       # 一份的克重
    kcal: Decimal           # 一份的熱量
    protein_g: Decimal
    fat_g: Decimal
    carb_g: Decimal
```

**Preset 範例：**

| canonical_key | portion_unit | weight_g | kcal |
|---------------|-------------|---------|------|
| `boiled_egg` | `pcs` | 50g | 78 kcal |
| `generic_protein` | `plate` | 180g | 260 kcal |
| `generic_condiment` | `tbsp` | 15g | 35 kcal |
| `generic_garnish` | `tbsp` | 6g | 8 kcal |
| `bubble_milk_tea` | `cup` | 500g | 400 kcal |

---

### 3.6 Special Guard — 包裝飲料偵測

`apply_special_source_guards()` 在來源選擇完成後執行最後一道保護：

**觸發條件：**
1. `is_packaged_drink(food_name, normalized_food_name)` 回傳 `True`
2. 當前 canonical key 是 `generic_mixed_meal`（代表關鍵字沒有精確命中）

**效果：** 改用 `generic_unsweetened_drink` preset（每 100g 僅 2 kcal），避免把包裝水或茶飲算成一碗套餐的熱量。

## 4. 營養來源優先順序總表

| 優先順序 | `nutrition_source` | `is_estimated` | 說明 |
|---------|-------------------|----------------|------|
| 1（最優）| `rag_official` | `False` | RAG 向量命中衛福部資料 |
| 2 | `official_source` | `False` | 精選關鍵字目錄精確命中 |
| 3 | `preset` | `False` | `CANONICAL_FOOD_KEYS` 直接命中 preset |
| 4 | `alias_mapping` | `True` | alias 別名映射後命中 preset |
| 5 | `keyword_fallback` | `True` | 關鍵字規則命中 preset |
| 6 | `drink_fallback` | `True` | Special Guard 改用飲料 preset |
| 7（最差）| `default_fallback` | `True` | 完全沒命中，使用 `generic_mixed_meal` |

`is_estimated = True` 的來源在前端會顯示「估算」標記。

## 5. 已知問題與實際案例

### 案例 A：wasabi 掉入 `generic_mixed_meal`

**症狀：** AI 回傳 `food_name: "Wasabi"`，系統算出熱量 420 kcal（一碗套餐的熱量）。

**原因追蹤：**

```
normalized_food_name: "wasabi"

1. CANONICAL_FOOD_KEYS → 沒有 "wasabi"           ✗
2. ALIAS_MAPPING → 沒有 "wasabi"                  ✗
3. KEYWORD_RULES：
   - generic_condiment: ("sauce", "dressing", "dip", "醬", "醬汁")
     → "wasabi" 不在清單中                        ✗
   - generic_protein: ("chicken", "beef", ...)
     → "wasabi" 不在清單中                        ✗
4. default_fallback → "generic_mixed_meal"        ← 這裡出錯
```

**修正方式：** 在 `food_mapping.py` 的 `KEYWORD_RULES` 中補上：

```python
("generic_condiment", ("sauce", "dressing", "dip", "醬", "醬汁", "wasabi", "soy sauce", "ponzu")),
```

---

### 案例 B：shrimp 的份量單位錯誤

**症狀：** AI 回傳 `portion_value: 3, portion_unit: "pcs"`，系統算出熱量 780 kcal（3 × 260 kcal，等於 3 盤主食蛋白質）。

**原因追蹤：**

```
normalized_food_name: "shrimp"

KEYWORD_RULES:
  → "shrimp" 在 generic_protein 清單中           ✓

generic_protein preset:
  portion_unit = "plate", weight_g = 180g, kcal = 260

使用者輸入 portion_unit = "pcs"（個）
resolve_portion: pcs ≠ plate，fallback → multiplier = 3.0
結果：3 × 260 = 780 kcal                        ← 不合理
```

**修正方式：** 在 `portion_resolution.py` 的 `NUTRITION_PRESETS` 新增 shrimp 專屬 preset，並在 `food_mapping.py` 的 `CANONICAL_FOOD_KEYS` 與 `KEYWORD_RULES` 對應更新：

```python
# portion_resolution.py
"shrimp": NutritionPreset("pcs", Decimal("15.00"), Decimal("16.00"),
                           Decimal("3.00"), Decimal("0.20"), Decimal("0.10")),
# → 3 隻蝦 = 3 × 16 = 48 kcal，合理
```

## 6. 新增或修正食物資料的方法

### 新增一個有 preset 的食物

需要異動三個地方：

**步驟 1：** `food_mapping.py` — 加入 canonical key

```python
CANONICAL_FOOD_KEYS = frozenset({
    ...
    "shrimp",   # 新增
})
```

**步驟 2：** `portion_resolution.py` — 加入 preset

```python
NUTRITION_PRESETS = {
    ...
    "shrimp": NutritionPreset("pcs", Decimal("15.00"), Decimal("16.00"),
                               Decimal("3.00"), Decimal("0.20"), Decimal("0.10")),
}
```

**步驟 3：** `food_mapping.py` — 確認關鍵字或別名能命中

```python
# 方式 A：加 alias
ALIAS_MAPPING["prawn"] = "shrimp"

# 方式 B：加 keyword 規則
("shrimp", ("shrimp", "prawn", "蝦")),   # 在 KEYWORD_RULES 適當位置插入
```

### 修正關鍵字分類錯誤（如 wasabi）

只需改 `food_mapping.py` 的 `KEYWORD_RULES`，在對應的 tuple 中加入新關鍵字即可。注意 `KEYWORD_RULES` 是有序的，越前面優先。

### 讓 RAG 覆蓋更多食物

執行兩支腳本即可，不需改程式碼：

```powershell
uv run python scripts/import_nutrition_xlsx.py --xlsx "衛福部食品營養成分資料庫.xlsx"
uv run python scripts/generate_embeddings.py
```

RAG 命中的食物會標記 `nutrition_source = "rag_official"`，`is_estimated = False`。
